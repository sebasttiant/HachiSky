# Issuer profiles

## Objective
Reusable issuer profiles (HachiSky is the platform, not necessarily the issuer): list, create, edit, default, deactivate/reactivate; one logo per profile; bank accounts tied to their issuer. Preserve existing data.

## Problem
`issuer_settings` is a singleton (CHECK id = 1). Working for another entity means overwriting the only issuer. Logo and bank accounts are global.

## Scope (authorized 2026-10-04)
- Configuración > Emisores: list (name, identification, status, default mark), create, edit with the existing fields, default, deactivate/reactivate (no physical delete), logo per profile (upload, view, replace) through the C2 pipeline and immutable versions.
- Bank accounts belong to one issuer; shown in forms and lists; no mixing.
- Migration 0006 keeps the current issuer (with logo, payment terms, audit), its logo versions and bank accounts. Only unambiguous links; ambiguity is reported, never guessed. Applied migrations untouched.
- Admin-only + audit. No new dependencies. Signers unchanged.

Out of scope: drafts, issuing, numbering, voiding, PDF, reports, client logo, DIAN, multi-tenant, signer redesign, bank format rules, commits/push/merge/VPS (not authorized).

## Decisions
- New table `issuer_profile` (uuid). `is_default` unique among rows (partial unique index) and `CHECK (NOT is_default OR active)`.
- **Default deactivation rule:** the default issuer cannot be deactivated; the admin must first make another issuer the default. Nothing is reassigned silently. Creating the first issuer makes it the default only when no default exists (explicit message); later ones are not default unless chosen.
- Unique identification (type, number) across profiles, inactive included (reactivate instead of duplicating), same as signers.
- Logo ownership via an immutable `issuer_logo` table (image id → issuer), so `billing_image` rows are never updated; `issuer_profile(current_logo_image_id, id)` references `issuer_logo(image_id, issuer_profile_id)`.
- `bank_account.issuer_profile_id` nullable at the DB level so pre-existing accounts with no unambiguous issuer stay unassigned (reported); the app requires an active issuer on create and update.
- `issuer_settings` is dropped in 0006 after its row is copied (no duplicate source of truth). Demo DB backed up first.
- Old `/settings/issuer` redirects to `/settings/issuers`; old upload route replaced by `/api/billing/uploads/issuers/[id]/logo`.
- Logo upload diagnosis (2026-10-04, real headless Chrome at 127.0.0.1:3104, before any change): valid PNG → 201 "Logo guardado." + preview; invalid file → 400 "Solo se aceptan imágenes PNG o JPG.".
